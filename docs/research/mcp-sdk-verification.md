## Minimal current tool-registration snippet (v2, for reference only — no source code was written for the project)

```ts
import { McpServer } from '@modelcontextprotocol/server';
import { serveStdio } from '@modelcontextprotocol/server/stdio';
import * as z from 'zod/v4';

serveStdio(() => {
  const server = new McpServer({ name: 'meta-content-mcp', version: '0.1.0' });

  server.registerTool(
    'meta_list_accounts',
    {
      title: 'List Meta accounts',
      description: 'List connected Facebook Pages and Instagram professional accounts',
      inputSchema: z.object({}),
      outputSchema: z.object({
        accounts: z.array(z.object({ id: z.string(), name: z.string(), type: z.enum(['page', 'ig_professional']) })),
      }),
      annotations: { readOnlyHint: true, destructiveHint: false, idempotentHint: true, openWorldHint: true },
    },
    async () => {
      const accounts = [/* ... */];
      return {
        content: [{ type: 'text', text: JSON.stringify(accounts) }],
        structuredContent: { accounts },
      };
    },
  );

  return server;
});
```

## Overall recommendation

No conflicting official sources were found on any of the four items — PROMPT.md's section 2 claims about the MCP spec and Claude Code subagents check out as written, with the small additions noted above (Roots/Logging deprecated alongside Sampling; `fable` is a valid model alias; `@modelcontextprotocol/core` is a third package alongside `server`/`client`; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` exists as a stronger override). The safest implementation path:

- Depend on `@modelcontextprotocol/server` / `@modelcontextprotocol/client` `^2.0.0` (v2) with `zod ^4.2.0`, since v2 is confirmed current and stable, but keep the migration guide (`ts.sdk.modelcontextprotocol.io/v2/migration/upgrade-to-v2.html`) and the codemod (`@modelcontextprotocol/codemod`) noted in an ADR in case any v2 sub-page/API turns out incomplete once installed (a couple of v2 doc sub-pages 404'd during this check — re-verify against the installed package's TypeScript types, which are the ultimate source of truth, before finalizing tool signatures).
- Design `meta_confirm` and the `*_prepare` flow around the **handler-return-value** MRTR contract (`inputRequired.elicit(...)`), not a long-lived push channel — this is a bigger implementation detail than PROMPT.md's wording implies, but it fits the already-planned two-phase prepare/confirm design well.
- Do not rely on MCP Sampling (or Roots/Logging) for anything long-lived; call the Anthropic API directly for the runtime LLM router, which is already PROMPT.md's plan.
- Router model ids: `claude-haiku-4-5` (fast), `claude-sonnet-5` (balanced), `claude-opus-5` (deep), with batch (50% off) and prompt caching (up to 90% off reads) both available and stackable.
